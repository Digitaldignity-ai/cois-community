# CoIS Community

**Help shape continuity, privacy and security for intelligent systems.**

CoIS means **Continuity of Intelligent Systems**. We are exploring how people and AI collaborators can carry enough useful context forward: sources, corrections, uncertainty, accomplishments, relationships and a clear stopping point. Our design direction is local-first, with explicit choices about what is retained and who can retrieve it.

This is the public place to suggest improvements, ask questions and contribute to that work. You do not need to be a developer or a member of Digital Dignity to participate. A GitHub account is needed to post or submit a pull request.

## Start here

| You want to… | Go here |
| --- | --- |
| Propose something concrete | [Open a suggestion](https://github.com/Digitaldignity-ai/cois-community/issues/new/choose) |
| Explore an idea or ask a question | [Discussions](https://github.com/Digitaldignity-ai/cois-community/discussions) |
| Improve these documents or a proposal | [Contribution guide](CONTRIBUTING.md) |
| Report a suspected vulnerability or data exposure | [Private reporting instructions](SECURITY.md) |

Useful topics include:

- **Privacy:** consent, retention, deletion, visibility, sharing and meaningful user control.
- **Security:** scoped access, identity, safe defaults, recovery and clear permission boundaries.
- **Continuity and recall:** original sources, corrections, uncertainty, relevance and useful reorientation.
- **Accessibility and usability:** interfaces people can understand and ways to recover when something fails.
- **Interoperability:** practical ways for different tools and assistants to collaborate without losing attribution.

A short explanation of the problem and who it affects is enough to start. Synthetic examples, sketches and links to public research are welcome.

## What happens to a suggestion?

New issues start at `status: proposed`. Maintainers can move them through review, record a decision, and link implementation evidence. An accepted idea is not a promise of delivery. `status: verified` requires a specific check and its limits; an encouraging discussion or passing demo alone does not establish broad reliability.

We preserve contributor credit, reasons for decisions and corrections to earlier conclusions. See the [contribution guide](CONTRIBUTING.md) for the status definitions.

## Privacy work and public contributions

Claude is contributing to the ongoing privacy work, as David reported when opening this community space. That work is in progress. This repository invites input; it does not claim a completed privacy audit or security certification.

Issues, discussions, pull requests and commit history here are public. Share only material you have permission to publish. Use invented examples instead of private conversations, memory records, credentials or real infrastructure details. [Security reports have a separate private route](SECURITY.md).

Reading this repository or submitting a proposal does not grant access to private notebooks, runtime systems or anyone else's data. Changes are reviewed by maintainers.
