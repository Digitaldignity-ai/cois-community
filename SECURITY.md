# Security and private reporting

Public security design suggestions belong in the issue forms. **Suspected vulnerabilities, exposed credentials or data exposure belong in a private report.**

Use [GitHub private vulnerability reporting](https://github.com/Digitaldignity-ai/cois-community/security/advisories/new) for this repository or a suspected issue concerning the CoIS work discussed here. Reports go to authorized repository maintainers through GitHub. This route is private to that reporting process; it is not a local-only channel.

Include a short description, affected component if known, likely impact, and minimal synthetic or redacted reproduction steps. Do not submit passwords, active tokens, full private datasets or other people's personal information. Maintainers may request a safer reproduction.

If the private reporting form is unavailable, start a [public discussion](https://github.com/Digitaldignity-ai/cois-community/discussions/new) containing only: “Please provide a private security contact.” Do not include vulnerability or exposure details in that public discussion.

This documentation and suggestions repository does not define supported releases or claim that every CoIS component has been audited. There is no promised response deadline or bounty program. Avoid testing live systems without their owner's authorization. A report does not authorize remediation, data access or publication of a private advisory.

If you accidentally publish a secret, revoke or rotate it at its issuer promptly, then use the private reporting route. Deleting a public post alone cannot guarantee removal from copies or history.
